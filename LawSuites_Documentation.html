LawSuites — Code Documentation

Project Type: University Semester Project — MERN Stack (MongoDB, Express, React, Node.js)

Purpose: A Pakistani legal services platform where users describe their problem, an AI recommends the right type of lawyer, and an admin manages the case from start to finish.

1. What the Project Does (Simple Overview)

When someone has a legal problem in Pakistan, they often do not know which type of lawyer to hire. LawSuites solves this in 3 steps:

  1. User types their problem in plain Urdu or English.
  2. The AI reads the text, counts legal keywords, and recommends the best attorney type.
  3. The user registers, a case is created automatically, and an admin manages it from a dashboard.

5 Attorney Types: Criminal Law, Tax & Filing, Real Estate, Family Law, Women's Rights

2 User Roles: Client (registers and tracks their case) and Admin (manages all cases)

3. Backend Files — Simple Explanation

server.js — Starting Point

This is the first file that runs when you type npm run dev. It does 4 things:

  1. Loads secret values from the .env file (database password, port number).
  2. Connects to MongoDB Atlas (the cloud database).
  3. Registers all URL routes so the app knows what to do when a request arrives.
  4. Starts listening for requests on port 5000.

config/db.js — Database Connection

One job only: connect to MongoDB Atlas using the connection string from .env. If connection fails, it stops the server and shows an error. If it works, it prints "MongoDB Connected".

.env — Secret Configuration File

This file is never shared or uploaded to GitHub. It contains:

  • MONGO_URI — the MongoDB Atlas connection string (includes username and password)
  • JWT_SECRET — a secret key used to sign login tokens
  • PORT — 5000 (the port the server runs on)
  • CLIENT_URL — http://localhost:3000 (the frontend address)

5. Controllers — The Business Logic

controllers/aiController.js — The AI Engine

This is the most important file. It does NOT use ChatGPT or any paid AI. It is a custom keyword scoring algorithm written in plain JavaScript.

How it works:

  1. There are 5 attorney types, each with a list of 80-100 keywords (English + Urdu/Roman Urdu).
  2. The user's problem text is converted to lowercase.
  3. For each keyword in each attorney type, it checks how many times that word appears in the text.
  4. The type with the highest count wins.
  5. Confidence % = (top score ÷ total of all scores) × 100.
  6. Experience level is decided by checking if the text contains "severe" words (like murder, fraud, kidnapping) → Senior, or mild words (like advice, filing, basic) → Junior.

Urdu keywords used (examples):

  • Criminal: qatl, thana, FIR, katta, dacoity, bail, arrest
  • Real Estate: qabza, zameen, kiraya, fard, intiqal, tenant
  • Family: talaq, khula, mehr, nafqa, bachay, custody
  • Tax: fbr, ntn, strn, filer, returns, gst, audit
  • Women's Rights: harassment, zulm, dowry, domestic violence, saas

What it returns: recommendedType, experienceLevel, confidence percentage, confidenceLabel (high/medium/low), and allScores (all 5 scores for the breakdown chart).

6. Middleware — Security Guard

middleware/auth.js

Every protected route passes through this file first, before reaching the controller.

protect() — Checks if a valid JWT token is attached to the request header. If yes, it reads the token, finds the user's ID and role, and stores it in req.user. If no token or invalid token → returns 401 Unauthorized.

adminOnly() — Runs after protect(). Checks if req.user.role === "admin". If not → returns 403 Forbidden.

How JWT works in simple terms:

  1. User logs in → server creates a token (like a digital pass) and sends it back.
  2. Frontend saves the token in localStorage.
  3. Every API request includes the token in the header: Authorization: Bearer <token>
  4. auth.js verifies the token on every request.
  5. If token is valid → request is allowed. If not → request is blocked.

9. Frontend Files — Simple Explanation

services/api.js — Central API Hub

All API calls go through this one file. It uses Axios (a tool for making HTTP requests). Two things happen automatically:

  • Request interceptor: Before every request, it reads the token from localStorage and adds it to the header. So you never have to do it manually.
  • Response interceptor: If any request returns 401 (token expired or invalid), it automatically clears the storage and sends the user to the login page.

context/AuthContext.js — Global Login State

React's Context API is used here so that all pages can know if someone is logged in, without passing data down through props manually.

It provides 4 things to every component:

  • user — the logged-in user object (name, role, id) or null
  • login(token, userData) — saves token and user to localStorage
  • logout() — clears localStorage and redirects to home
  • isAdmin — true if user.role is "admin"

App.js — Routes and Protection

This file connects all pages to their URLs using React Router. It also contains two guard components:

  • PrivateRoute: If user is not logged in → redirect to /login. If user is logged in but not admin and tries to visit /admin → redirect to /dashboard.
  • PublicRoute: If user is already logged in and tries to visit /login or /register → redirect them to their dashboard automatically.

12. How Data Flows Through the App

Example: User types a problem and registers

  1. User types problem text in AIWidget.js
  2. AIWidget calls aiAPI.match(text) from api.js
  3. api.js sends POST request to /api/ai/match
  4. Server receives it in aiRoutes.js → calls aiController.matchAttorney()
  5. aiController scores the text, returns recommended type + confidence
  6. AIWidget shows the result to the user
  7. User clicks Register → goes to Register.js with the result pre-filled
  8. User fills form and submits → calls clientAPI.register()
  9. Server: clientController.register() hashes password, creates Client document, creates Case document, returns JWT
  10. AuthContext.login() saves token and user to localStorage
  11. App.js redirects to /dashboard
  12. Dashboard.js calls caseAPI.getMyCases() → shows the case
